## Brew Browser 0.7.4 / native 0.3.4

Tauri is the macOS 13+ / Linux build; native is the macOS 26 SwiftUI build
(native 0.3.4 ≙ Tauri 0.7.4). Both are signed + notarized.

## Fixes

### "Upgrade failed" no longer cries wolf when most of an upgrade succeeded

A bulk `brew upgrade` — especially with the greedy toggle on, which targets
self-updating casks — routinely upgrades dozens of packages and then exits
non-zero because one cask needed an administrator password, had its app moved,
or is incompatible with your macOS. The old check treated any non-zero exit as
a flat **"Upgrade failed,"** even when almost everything upgraded. That was the
single largest source of misfiled "Upgrade failed" reports.

Both builds now read brew's own output and, on a partial success, show the real
outcome — *"Upgraded 74 — 2 couldn't upgrade automatically"* — and list each
package that didn't, with a **Run in Terminal** button next to it. The button
opens Terminal running `brew upgrade <name>`, where `sudo` / Touch ID can
actually prompt (a GUI can't). The card title softens to **"Upgrade
incomplete"** when some packages did upgrade.

The button is additive: it appears even alongside a known-failure explanation
(for example the cask-needs-your-password notice), so there's always a
one-click way to finish the stragglers.

### brew-browser notices a Terminal-side upgrade finished

Because the Terminal command runs on its own, the app gets no "done" signal.
Three things now keep the interface current without a manual refresh: it
re-reads Homebrew when the window regains focus (so any change you make in a
terminal is picked up), a **Re-check** button sits on the failure card, and
after a hand-off the app briefly watches for that package to leave the
outdated list and refreshes the moment it does.
